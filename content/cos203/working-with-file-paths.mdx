# Working With File Paths in Python

In the previous topic, we learned that Windows uses backslashes (`\`) for file paths, while Mac and Linux use forward slashes (`/`). If you manually type a file path as a string (like `"C:\Users\David\file.txt"`), your program is instantly tied to that specific operating system. If someone runs it on a Mac, the program will crash because Macs don't understand `C:\`.

To solve this cross-platform nightmare, Python introduced the `pathlib` module. `pathlib` takes the raw strings and turns them into intelligent **Path Objects**. These objects automatically translate themselves into the correct format for whatever operating system the code is currently running on.

## Creating Path Objects

Before we can use `pathlib`, we must import it. We specifically want the `Path` class.

```python
from pathlib import Path
```

### Worked Example 1: Creating Paths from Strings

You can create a `Path` object simply by passing a string into the `Path()` constructor.

```python
# Even if you are on Windows, you should pass FORWARD slashes to pathlib.
# Pathlib will automatically translate them to backslashes in the background!
my_path = Path("C:/Users/David/Documents/hello.txt")

print(type(my_path)) # Output: <class 'pathlib.WindowsPath'> (or PosixPath on Mac)
```

> **Warning for Windows Users:** If you *must* paste a Windows path with backslashes into your code, you must prefix the string with an `r` (creating a **raw string**). This stops Python from misinterpreting `\n` or `\t` as newlines or tabs.
> `path = Path(r"C:\Users\David\Desktop\hello.txt")`

### Worked Example 2: Dynamic Paths (Home and CWD)

Hardcoding your name (`"C:/Users/David/"`) into a script is a terrible idea. What if someone named Sarah runs the script? The folder `C:/Users/David/` won't exist on her computer!

Instead, we use dynamic class methods that ask the operating system where things are.

1. **`Path.home()`**: Returns the path to the current user's home folder, regardless of their name or OS.
2. **`Path.cwd()`**: Returns the Current Working Directory (the folder where the Python script is currently running from).

```python
# Get the home directory dynamically
home_folder = Path.home()

# On David's Mac, this will be: /Users/David
# On Sarah's Windows PC, this will be: C:\Users\Sarah
print(home_folder) 
```

### Worked Example 3: The Magic Slash Operator

`pathlib` does a very clever trick with Python's division operator (`/`). If you place a `/` between a Path object and a string, `pathlib` stitches them together into a new, longer file path, using the correct slashes for the current OS!

```python
# Start at the user's home directory
base_path = Path.home()

# Stitch folders and file names together seamlessly!
# We don't have to worry about whether to use \ or /
final_path = base_path / "Documents" / "Projects" / "hello.txt"

print(final_path)
# Windows Output: C:\Users\Sarah\Documents\Projects\hello.txt
# Mac Output: /Users/David/Documents/Projects/hello.txt
```

## Absolute vs. Relative Paths

When giving directions to a coffee shop, you can do it in two ways:
1. **Absolute:** "The coffee shop is at 123 Main Street, New York, NY." (This works no matter where the person currently is).
2. **Relative:** "Take a left out the front door, then walk two blocks." (This *only* works if the person is standing exactly where you expect them to be).

File paths work exactly the same way.

- **Absolute Path:** A path that starts all the way from the root directory (`C:\` or `/`). It is a complete address.
- **Relative Path:** A path that starts from wherever the script is currently running (the Current Working Directory).

```python
from pathlib import Path

# Absolute Path (Starts at the Root)
abs_path = Path("C:/Users/David/photos/cat.jpg")
print(abs_path.is_absolute()) # Output: True

# Relative Path (Starts from wherever we are right now)
rel_path = Path("photos/cat.jpg")
print(rel_path.is_absolute()) # Output: False

# We can turn a relative path into an absolute path using .resolve()
full_path = rel_path.resolve()
```

## Dissecting a Path Object

Once you have a `Path` object, you have access to a wealth of properties that allow you to rip the path apart and inspect its pieces. This is infinitely easier than trying to slice strings manually.

```mermaid
graph LR
    Full[C:/Users/David/data.txt] --> Parent[C:/Users/David]
    Full --> Name[data.txt]
    Name --> Stem[data]
    Name --> Suffix[.txt]
```

Let's look at the code to extract these pieces:

```python
from pathlib import Path

file_path = Path("C:/Users/David/documents/report.pdf")

# 1. .parent: Gets the folder containing the file
print(file_path.parent) # Output: C:\Users\David\documents

# 2. .name: Gets the full file name with the extension
print(file_path.name)   # Output: report.pdf

# 3. .stem: Gets JUST the file name, without the extension
print(file_path.stem)   # Output: report

# 4. .suffix: Gets JUST the extension
print(file_path.suffix) # Output: .pdf
```

## Checking for Existence

Just because you create a `Path` object for `"C:/Users/David/unicorn.txt"` does not mean a file called `unicorn.txt` actually exists on the computer. A Path object is just a representation of an address.

Before trying to read or write to a path, you should always check if it exists in reality.

```python
from pathlib import Path

my_file = Path("C:/Users/David/unicorn.txt")

# Check if the path exists on the hard drive
if my_file.exists():
    print("The file is real!")
else:
    print("This file does not exist.")
    
# We can also be specific: Is it a file, or is it a folder?
print(my_file.is_file()) # Output: False
print(my_file.is_dir())  # Output: False
```

## Key Takeaways
- The `pathlib` module is mandatory for writing cross-platform Python code. It translates paths for Windows, Mac, and Linux automatically.
- Always use `Path.home()` or `Path.cwd()` instead of hardcoding root directories.
- The forward slash `/` is overloaded by `pathlib` to stitch paths together cleanly.
- An **Absolute path** is a full address from the root; a **Relative path** depends on your current location.
- Path objects provide properties like `.parent`, `.name`, `.stem`, and `.suffix` to easily extract parts of the address.

## Exam Tips
- **The Raw String Trick:** If an exam shows `Path("C:\new\text.txt")`, recognize that this will fail. The `\n` and `\t` will trigger escape sequences. It must be written as a raw string: `Path(r"C:\new\text.txt")` or with forward slashes.
- **Definition Check:** Be able to explicitly define the difference between `.name` (the whole file name, e.g., `image.png`) and `.stem` (just the name, e.g., `image`).
