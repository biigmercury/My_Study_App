## Why Study O(n²) Sorting Algorithms?

Before we can appreciate fast sorting (Merge Sort, Quick Sort), we need to understand slow sorting. The three algorithms in this topic — Bubble Sort, Selection Sort, and Insertion Sort — are all $O(n^2)$. They are too slow for large datasets, but:

1. They are simple enough to prove correct and analyse in full detail
2. They introduce the techniques (swap, shift, select minimum) used in advanced algorithms
3. Insertion Sort is actually fast for small or nearly-sorted arrays — it is used as a base case in many hybrid sorts

**Analogy:** Learning to ride a bicycle before a motorbike. The physics is the same; the complexity is different.

## 1. Bubble Sort

### The Idea

Compare adjacent pairs of elements. If they are in the wrong order, swap them. Each full pass through the array "bubbles" the largest unsorted element to its correct position at the end.

### Pseudocode

```
ALGORITHM BubbleSort(A, n):
  FOR i FROM 0 TO n - 2 DO:
    FOR j FROM n - 1 DOWNTO i + 1 DO:
      IF A[j] < A[j - 1] THEN
        SWAP A[j] AND A[j - 1]
```

(Alternatively, the outer loop runs from $0$ to $n-2$ and the inner loop runs from $i+1$ to $n-1$.)

### Step-by-Step Trace

Array: $A = [5, 3, 8, 4, 2]$

**Pass 1** (bubble max to position 4):
- Compare $A[1]=5$ and $A[2]=3$: $5 > 3$ → swap → $[3, 5, 8, 4, 2]$
- Compare $A[2]=5$ and $A[3]=8$: $5 < 8$ → no swap → $[3, 5, 8, 4, 2]$
- Compare $A[3]=8$ and $A[4]=4$: $8 > 4$ → swap → $[3, 5, 4, 8, 2]$

Wait — this variant scans rightward. Let me use the downward variant from the pseudocode above (scan from right to left):

**Pass 1 ($i = 0$)**, inner $j$ from $4$ down to $1$:
- $j=4$: $A[4]=2, A[3]=4$; $2 < 4$ → swap → $[5,3,8,2,4]$
- $j=3$: $A[3]=2, A[2]=8$; $2 < 8$ → swap → $[5,3,2,8,4]$
- $j=2$: $A[2]=2, A[1]=3$; $2 < 3$ → swap → $[5,2,3,8,4]$
- $j=1$: $A[1]=2, A[0]=5$; $2 < 5$ → swap → $[2,5,3,8,4]$

After pass 1: $[2, 5, 3, 8, 4]$. The minimum (2) has bubbled to the front.

**Pass 2 ($i = 1$)**, inner $j$ from $4$ down to $2$:
- $j=4$: $4 < 8$ → swap → $[2,5,3,4,8]$
- $j=3$: $4 > 3$ → no swap
- $j=2$: $3 < 5$ → swap → $[2,3,5,4,8]$

After pass 2: $[2, 3, 5, 4, 8]$

**Pass 3 ($i = 2$)**: After this, $[2, 3, 4, 5, 8]$ — sorted.

### Counting Operations

For each value of $i$ from $0$ to $n-2$, the inner loop runs $(n-1-i)$ iterations.

$$T(n) = \sum_{i=0}^{n-2} (n-1-i) = (n-1) + (n-2) + \cdots + 1 = \frac{n(n-1)}{2}$$

$$T(n) = \frac{n^2 - n}{2} = O(n^2)$$

For $n = 10$: 45 comparisons. For $n = 1000$: 499,500. For $n = 1,000,000$: about 500 billion.

### Complexities Summary

| Case | Complexity | Why |
|---|---|---|
| Best | $O(n)$ | Array already sorted — with early-exit optimisation, one pass with no swaps |
| Average | $O(n^2)$ | Random order |
| Worst | $O(n^2)$ | Array in reverse order |

## 2. Selection Sort

### The Idea

In each pass, **find the minimum element** in the unsorted portion and swap it into its correct position at the front. After $k$ passes, the first $k$ elements are sorted.

### Pseudocode

```
ALGORITHM SelectionSort(A, n):
  FOR i FROM 0 TO n - 2 DO:
    min_idx = i
    FOR j FROM i + 1 TO n - 1 DO:
      IF A[j] < A[min_idx] THEN
        min_idx = j
    IF min_idx != i THEN
      SWAP A[i] AND A[min_idx]
```

### Step-by-Step Trace

Array: $A = [64, 25, 12, 22, 11]$

**Pass $i=0$:** Find min of $A[0..4]$: min is $11$ at index 4. Swap $A[0]$ and $A[4]$: $[11, 25, 12, 22, 64]$

**Pass $i=1$:** Find min of $A[1..4]$: min is $12$ at index 2. Swap $A[1]$ and $A[2]$: $[11, 12, 25, 22, 64]$

**Pass $i=2$:** Find min of $A[2..4]$: min is $22$ at index 3. Swap $A[2]$ and $A[3]$: $[11, 12, 22, 25, 64]$

**Pass $i=3$:** Find min of $A[3..4]$: min is $25$ at index 3. No swap needed. Done.

Result: $[11, 12, 22, 25, 64]$ ✓

### Counting Operations

The inner loop runs $(n - 1 - i)$ iterations for each $i$. Same count as Bubble Sort:

$$T(n) = \sum_{i=0}^{n-2} (n-1-i) = \frac{n(n-1)}{2} = O(n^2)$$

**Key observation:** Selection sort always performs exactly $\dfrac{n(n-1)}{2}$ comparisons, regardless of whether the input is sorted or not. It has no best case — it is $O(n^2)$ in all cases.

| Case | Comparisons | Swaps |
|---|---|---|
| All cases | $\dfrac{n(n-1)}{2}$ | At most $n-1$ |

Selection sort makes **at most $n-1$ swaps** — this makes it advantageous when swapping is expensive.

## 3. Insertion Sort

### The Idea

Build a sorted sub-array from left to right. For each new element, **insert it into the correct position** in the already-sorted portion by shifting larger elements right.

**Analogy:** Sorting a hand of playing cards. You pick up cards one at a time and insert each into its correct position among the cards you are already holding.

### Pseudocode

```
ALGORITHM InsertionSort(A, n):
  FOR j FROM 1 TO n - 1 DO:
    key = A[j]             // element to insert
    i = j - 1              // look left
    WHILE i >= 0 AND A[i] > key DO:
      A[i + 1] = A[i]      // shift right
      i = i - 1
    A[i + 1] = key         // insert in correct position
```

### Step-by-Step Trace

Array: $A = [8, 4, 3, 7, 6]$

**$j=1$:** key $= 4$. Compare with $A[0]=8$: $8 > 4$, shift right. Insert $4$ at index 0. → $[4, 8, 3, 7, 6]$

**$j=2$:** key $= 3$. Compare $A[1]=8$: shift. Compare $A[0]=4$: shift. Insert $3$ at 0. → $[3, 4, 8, 7, 6]$

**$j=3$:** key $= 7$. Compare $A[2]=8$: shift. Compare $A[1]=4$: $4 < 7$, stop. Insert at 2. → $[3, 4, 7, 8, 6]$

**$j=4$:** key $= 6$. Compare $A[3]=8$: shift. Compare $A[2]=7$: shift. Compare $A[1]=4$: $4 < 6$, stop. Insert at 2. → $[3, 4, 6, 7, 8]$

Result: $[3, 4, 6, 7, 8]$ ✓

### Counting Operations — Careful Analysis

The inner `WHILE` loop shifts $A[i]$ right when $A[i] > key$.

**Best case** (array already sorted): $A[j-1] \leq key$ for every $j$, so the `WHILE` loop never executes.

$$T_\text{best}(n) = \sum_{j=1}^{n-1} 1 = n - 1 = O(n)$$

**Worst case** (array in reverse order): For each $j$, the `WHILE` loop executes $j$ times (shifts all sorted elements right).

$$T_\text{worst}(n) = \sum_{j=1}^{n-1} j = 1 + 2 + \cdots + (n-1) = \frac{n(n-1)}{2} = O(n^2)$$

**Average case**: On average, each new element is inserted in the middle of the sorted portion — about $j/2$ shifts.

$$T_\text{avg}(n) = \sum_{j=1}^{n-1} \frac{j}{2} = \frac{1}{2} \cdot \frac{n(n-1)}{2} = \frac{n(n-1)}{4} = O(n^2)$$

## Comparison Table

| Property | Bubble Sort | Selection Sort | Insertion Sort |
|---|---|---|---|
| Best case | $O(n)$* | $O(n^2)$ | $O(n)$ |
| Average case | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ |
| Worst case | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ |
| Swaps | $O(n^2)$ | $O(n)$ | $O(n^2)$ (shifts) |
| Stable? | Yes | No | Yes |
| In-place? | Yes | Yes | Yes |

*with early-exit optimisation

**Stability:** A sorting algorithm is **stable** if equal elements preserve their original relative order. Bubble and Insertion are stable; Selection is not (swapping may move an equal element past another).

## Worked Example: Full Trace with Operation Count

**Problem:** Apply Insertion Sort to $A = [5, 2, 4, 6, 1, 3]$. Count total comparisons and shifts.

| $j$ | key | Array before | Shifts | Array after |
|---|---|---|---|---|
| 1 | 2 | $[5, 2, 4, 6, 1, 3]$ | 1 ($5 \to$) | $[2, 5, 4, 6, 1, 3]$ |
| 2 | 4 | $[2, 5, 4, 6, 1, 3]$ | 1 ($5 \to$) | $[2, 4, 5, 6, 1, 3]$ |
| 3 | 6 | $[2, 4, 5, 6, 1, 3]$ | 0 | $[2, 4, 5, 6, 1, 3]$ |
| 4 | 1 | $[2, 4, 5, 6, 1, 3]$ | 4 (all $\to$) | $[1, 2, 4, 5, 6, 3]$ |
| 5 | 3 | $[1, 2, 4, 5, 6, 3]$ | 3 ($4,5,6 \to$) | $[1, 2, 3, 4, 5, 6]$ |

Total shifts: $1 + 1 + 0 + 4 + 3 = 9$  
Total comparisons (each shift involves 1 comparison + 1 extra to stop): approximately $1+1+1+5+4 = 12$

Final sorted: $[1, 2, 3, 4, 5, 6]$ ✓

## Key Takeaway

> Bubble Sort, Selection Sort, and Insertion Sort all have $O(n^2)$ average and worst-case complexity, making them impractical for large $n$. However, Insertion Sort is $O(n)$ for nearly-sorted arrays — making it excellent in practice for small lists or finishing what a faster algorithm started. Counting operations precisely using summation formulas ($\sum_{i=1}^{n-1} i = n(n-1)/2$) is the foundation of all algorithm analysis.

## Exam Tips

**What lecturers test:**
- Trace any of the three sorts step-by-step on a 5–6 element array
- Compute the exact number of comparisons (as a formula in $n$)
- State which is best for nearly-sorted data (Insertion Sort)
- State which minimizes swaps (Selection Sort)
- Prove the $O(n^2)$ bound using the summation formula

**Common mistakes:**
- Forgetting that Selection Sort is $O(n^2)$ even in the best case
- Confusing "stable" with "in-place" — both Bubble and Insertion are both stable AND in-place
- Miscounting: the outer loop runs $n-1$ times, not $n$ times

**Likely question:**
> "Trace Insertion Sort on $[6, 3, 8, 1, 5]$. Show every step. Derive the worst-case time complexity. For which type of input does Insertion Sort perform best, and what is its complexity in that case?" (14 marks)
