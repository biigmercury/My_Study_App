Every algorithm you have studied so far has a polynomial running time — O(n log n), O(n²), O(n³). These are considered **tractable** (solvable in reasonable time). But there exists a class of problems where no known polynomial-time algorithm exists — and there is serious reason to believe none ever will. Understanding this boundary is one of the deepest ideas in all of computer science.

---

## The Central Question

All algorithm analysis so far has asked: "How fast can we solve this problem?"

NP-completeness theory asks a different question: **"How fast is it fundamentally impossible to solve this problem?"**

This is the study of **computational complexity** — not the complexity of a specific algorithm, but the inherent complexity of a problem itself.

---

## Tractable vs Intractable Problems

### Efficient Algorithms

An algorithm is considered **efficient** if its worst-case running time is **polynomial** — O(n^k) for some constant k.

Examples of tractable problems:
- Sorting: O(n log n) — tractable
- Shortest path (Dijkstra's): O((V+E) log V) — tractable
- Binary search: O(log n) — tractable
- Matrix multiplication: O(n³) — tractable (though slow for large n)

### Intractable Problems

An algorithm is **intractable** if no polynomial-time algorithm is known, and the best known algorithms require exponential time.

From the course manual:
> "Some problems are intractable, so there are no efficient solutions without settling for an approximation. This is true of a special class of problems called NP-complete problems."

When faced with an NP-complete problem, you have three options:
1. Use an exact algorithm that is exponential (only works for small inputs)
2. Use an **approximation algorithm** — a polynomial-time algorithm that gives an answer within a guaranteed factor of optimal
3. Use a **heuristic** — a fast algorithm that usually gives good answers but with no guarantee

## Complexity Classes

### Class P

**P** is the class of all decision problems (yes/no problems) that can be **solved in polynomial time**.

Decision problem: a problem with a yes/no answer. (e.g., "Is there a path of length ≤ k between u and v?" rather than "What is the shortest path?")

**P = the set of problems solvable in O(n^k) time for some constant k**

Examples in P:
- Is this array sorted? O(n)
- Is there a path from u to v in graph G? O(V+E) via BFS
- What is the minimum spanning tree? O(E log E)
- Does array contain value x? O(n)

### Class NP

**NP** (Non-deterministic Polynomial) is the class of all decision problems where a proposed **solution can be verified in polynomial time**, even if finding the solution might be hard.

**Key insight:** Verifying an answer is easy. Finding the answer might be hard.

**Example — Hamiltonian Cycle:**
- **Problem:** Does graph G contain a Hamiltonian cycle (a cycle that visits every vertex exactly once)?
- **Verification:** Given a proposed cycle, check if it visits every vertex exactly once. This is O(V) — easy to verify.
- **Finding:** No known polynomial-time algorithm for finding a Hamiltonian cycle.

**Example — 0/1 Knapsack (Decision version):**
- **Problem:** Is there a selection of items with total weight ≤ W and total value ≥ V?
- **Verification:** Given a selection, compute weight and value. O(n) — easy.
- **Finding:** Requires exponential search in worst case without DP.

### The Relationship

<FormulaBlock
  formula="P \subseteq NP"
  label="P is a subset of NP"
/>

Every problem in P is also in NP: if you can solve a problem in polynomial time, you can certainly verify a solution in polynomial time (just solve it again and compare).

**The fundamental open question:** Is **P = NP**?

If P = NP, then every problem whose solution can be quickly verified could also be quickly solved — including hard problems in cryptography, optimisation, and biology. Most researchers believe P ≠ NP, but this has never been proven. It is one of the seven Millennium Prize Problems, with a $1,000,000 reward for its resolution.

### Class NP-Complete

A problem X is **NP-complete** if:
1. X is in NP (solutions can be verified in polynomial time), AND
2. Every other problem in NP can be **reduced** (transformed) to X in polynomial time

If you could solve any single NP-complete problem in polynomial time, you could solve ALL NP problems in polynomial time — meaning P = NP.

### Class NP-Hard

A problem X is **NP-hard** if every problem in NP can be reduced to X in polynomial time — but X itself does not have to be in NP (it might not even have a verifiable solution).

NP-complete = NP ∩ NP-hard.

## The Travelling Salesman Problem (TSP)

The classic NP-hard problem in this course:

**Problem:** A salesman must visit each of n cities exactly once and return to the starting city. Given the distance between each pair of cities, find the tour of minimum total distance.

**Why it matters:**
- Has direct applications in logistics, circuit board drilling, DNA sequencing
- n cities means (n−1)!/2 possible routes — for n=20, that is over 60 trillion routes
- No polynomial-time algorithm known
- Brute force: O(n!) — completely infeasible for large n

**TSP is NP-hard** — proving this means that if anyone finds a polynomial-time solution to TSP, they solve P=NP.

### 2-Approximation for TSP (With Triangle Inequality)

When cities satisfy the triangle inequality (direct route ≤ indirect route), a greedy approximation gives a tour at most **twice the optimal length**:

1. Compute a Minimum Spanning Tree T using Kruskal's/Prim's — O(E log E)
2. Duplicate all edges of T
3. Find an Eulerian path in the resulting graph
4. Convert to Hamiltonian cycle (shortcut repeated vertices)

**Time:** O(n²). **Guarantee:** Result is no more than 2× the optimal tour length.

This is a **2-approximation algorithm** — it cannot find the optimal tour in polynomial time, but it finds a good one with a proven quality bound.

## Lower Bound for Comparison Sorting

This is another fundamental impossibility result: **no comparison-based sorting algorithm can do better than Ω(n log n)**.

### The Decision Tree Model

Any comparison-based sorting algorithm can be modelled as a **binary decision tree**:
- Each internal node = one comparison between two elements (A[i] < A[j]?)
- Each branch = result of comparison (yes or no)
- Each leaf = one possible sorted permutation of the input

For n elements, there are **n!** possible orderings. The decision tree must have at least **n! leaves** to correctly handle all possible inputs.

### Deriving the Lower Bound

A binary tree with L leaves has height at least ⌈log₂ L⌉.

For n! leaves:

<FormulaBlock
  formula="h \geq \lceil \log_2(n!) \rceil"
  label="Minimum height of decision tree"
/>

Using **Stirling's approximation**: log₂(n!) = Θ(n log n)

Therefore the height — which equals the **worst-case number of comparisons** — is at least Θ(n log n).

**Conclusion:** Any comparison-based sorting algorithm must make at least Ω(n log n) comparisons in the worst case. Merge Sort and Heap Sort achieve this bound — they are **asymptotically optimal**.

### What This Means Practically

- **Bubble Sort:** O(n²) — correct but not optimal
- **Insertion Sort:** O(n²) worst case — correct but not optimal
- **Merge Sort:** O(n log n) — **optimal** for comparison sorting
- **Heap Sort:** O(n log n) — **optimal** for comparison sorting
- Any claim of a comparison-based sort that beats O(n log n) is wrong — mathematically impossible

## Beating the Lower Bound — Non-Comparison Sorting

The Ω(n log n) lower bound only applies to **comparison-based** sorting. If we make assumptions about the input (e.g., integers in a bounded range), we can sort faster.

### Counting Sort — O(n + k)

**Assumption:** All elements are integers in range [0, k].

```
CountingSort(A, n, k):
  count[0..k] = 0
  for each element x in A:
    count[x]++              // count occurrences of each value
  for i = 1 to k:
    count[i] += count[i-1]  // cumulative counts (positions)
  for j = n-1 downto 0:
    output[count[A[j]]-1] = A[j]
    count[A[j]]--
```

**Time:** O(n + k) — linear when k = O(n)
**Space:** O(n + k)

Not a comparison sort — it uses the values themselves as array indices. Beats Ω(n log n) because it doesn't compare elements.

**Limitation:** Only works for integers in a known bounded range.

### Radix Sort — O(d(n + k))

For integers with d digits, sort digit by digit from least significant to most significant, using Counting Sort for each digit.

**Time:** O(d(n + k)) — effectively linear when d is constant
**Example:** Sorting 32-bit integers using base 256 needs only d=4 passes

## Common NP-Complete Problems

These problems appear frequently in exams and real applications:

| Problem | Decision version | Why it matters |
|---|---|---|
| SAT (Boolean Satisfiability) | Is there an assignment of variables that satisfies a formula? | First proven NP-complete (Cook, 1971) |
| Travelling Salesman | Is there a tour ≤ k? | Logistics, routing |
| Hamiltonian Cycle | Does G have a Hamiltonian cycle? | Graph theory |
| Knapsack | Can we get value ≥ V within weight W? | Resource allocation |
| Graph Colouring | Can we colour G with k colours (no adjacent vertices same colour)? | Scheduling, register allocation |
| Vertex Cover | Is there a vertex cover of size ≤ k? | Network design |

### Polynomial Reduction

To prove problem X is NP-complete, you:
1. Show X is in NP (verify solutions in polynomial time)
2. Show some known NP-complete problem Y reduces to X in polynomial time

If Y reduces to X, then X is at least as hard as Y. Since Y is NP-hard, X must be NP-hard too.

<Analogy>
Imagine you need to schedule exams so no two courses that share students conflict. With two colours (two time slots), this is easy — it's just checking if a graph is bipartite, which BFS can solve in O(V+E). With three or more colours (time slots), the problem becomes NP-complete — no efficient algorithm is known for the general case. This is Graph Colouring. The same structure (deciding if a colouring exists) appears in register allocation in compilers, frequency assignment in wireless networks, and Sudoku solving. Recognising these as the same underlying problem is what makes NP-completeness theory so powerful.
</Analogy>

<Takeaway>
P is the class of problems solvable in polynomial time. NP is the class verifiable in polynomial time (P ⊆ NP). NP-complete problems are the hardest in NP — solving one efficiently solves all of NP. Whether P = NP is the greatest open problem in computer science. The lower bound for comparison sorting (Ω(n log n)) is proven via the decision tree model — Merge Sort is optimal. Non-comparison sorts like Counting Sort and Radix Sort beat this bound by using structure of the data instead of comparisons. For NP-hard problems, use approximation algorithms that guarantee a solution within a factor of optimal.
</Takeaway>

Common confusion: NP does NOT mean "not polynomial" — it means "non-deterministic polynomial" (verifiable in polynomial time). Students often write "NP = not polynomial" which is wrong.
</ExamTip>
