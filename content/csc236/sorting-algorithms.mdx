Sorting is one of the most fundamental problems in computer science. Many other algorithms — like binary search — require data to be sorted first. Sorting algorithms are also a showcase for almost every algorithm design technique: brute force, divide-and-conquer, loop invariants, and greedy reasoning. This topic covers every sorting algorithm in your course, in the order you need to understand them.

---

## Why Sorting Matters

1. Many applications inherently need sorted data (e.g., banks sort cheques by number)
2. Sorting is a key subroutine — render engines sort objects by depth, search engines sort results by relevance
3. We can prove a mathematical lower bound: no comparison-based sort can do better than **O(n log n)**
4. Sorting provides the richest source of examples for algorithm analysis

**Evaluation criteria for any sorting algorithm:**
- Time complexity (best, average, worst case)
- Space complexity (does it need extra memory?)
- Stability (does it preserve the relative order of equal elements?)
- Simplicity (how hard is it to implement?)

## 1. Bubble Sort

### The Idea

Bubble Sort repeatedly compares **adjacent elements** and swaps them if they are in the wrong order. After each full pass through the array, the **largest unsorted element "bubbles"** to its correct position at the end.

After pass 1: the largest element is in place.
After pass 2: the second largest is in place.
After n−1 passes: the whole array is sorted.

### Pseudocode

```
Algorithm BubbleSort(A, n):
  for i = 0 to n-1 do
    for j = 0 to n-i-2 do
      if A[j] > A[j+1] then
        swap A[j] and A[j+1]
      end if
    end for
  end for
```

### Worked Example

Sort: **A = [5, 1, 4, 2, 8]**

**Pass 1** (i=0, inner loop j from 0 to 3):
- Compare A[0]=5 and A[1]=1 → swap → [**1**, 5, 4, 2, 8]
- Compare A[1]=5 and A[2]=4 → swap → [1, **4**, 5, 2, 8]
- Compare A[2]=5 and A[3]=2 → swap → [1, 4, **2**, 5, 8]
- Compare A[3]=5 and A[4]=8 → no swap
- Result after Pass 1: [1, 4, 2, 5, **8**] ← 8 is in place

**Pass 2** (i=1, inner loop j from 0 to 2):
- Compare A[0]=1 and A[1]=4 → no swap
- Compare A[1]=4 and A[2]=2 → swap → [1, **2**, 4, 5, 8]
- Compare A[2]=4 and A[3]=5 → no swap
- Result after Pass 2: [1, 2, 4, **5**, 8] ← 5 is in place

**Pass 3** (i=2): No swaps occur. Array is sorted.

**Final result: [1, 2, 4, 5, 8]** — sorted in 3 passes.

### Java Implementation

```java
// Bubble Sort — Java implementation
public static void bubbleSort(int[] A) {
    int n = A.length;
    // Outer loop: n-1 passes total
    for (int i = 0; i < n - 1; i++) {
        // Inner loop: compare adjacent pairs, decreasing range each pass
        for (int j = 0; j < n - i - 1; j++) {
            if (A[j] > A[j + 1]) {
                // Swap adjacent elements using temp variable
                int temp = A[j + 1];
                A[j + 1] = A[j];
                A[j] = temp;
            }
        }
    }
}
```

### Complexity Analysis

Bubble Sort performs approximately n(n−1)/2 comparisons in the worst case.

| Case | Condition | Time Complexity |
|---|---|---|
| Best | Array already sorted (with early exit optimisation) | O(n) |
| Average | Random order | O(n²) |
| Worst | Array in reverse order | O(n²) |

Space complexity: **O(1)** — sorts in-place, no extra memory needed.

**Advantages:** Simple, detects already-sorted lists with optimisation, no extra memory.
**Disadvantages:** Very slow for large datasets. Inefficient compared to Merge Sort or Quick Sort.

## 2. Selection Sort

### The Idea

Selection Sort divides the array into a **sorted portion** (left, initially empty) and an **unsorted portion** (right, initially the whole array). In each iteration, it **selects the smallest element** from the unsorted portion and swaps it with the first unsorted element.

### Pseudocode

```
Algorithm SelectionSort(A, n):
  for i = 0 to n-2 do
    min = i                    // assume current position is minimum
    for j = i+1 to n-1 do
      if A[j] < A[min] then
        min = j                // found a new minimum
      end if
    end for
    if min ≠ i then
      swap A[i] and A[min]     // put minimum in correct position
    end if
  end for
```

### Worked Example

Sort: **A = [64, 25, 12, 22, 11]**

**Pass 1** (i=0): Scan for minimum in [64, 25, 12, 22, 11] → min = 11 at index 4. Swap A[0] and A[4].
→ [**11**, 25, 12, 22, 64]

**Pass 2** (i=1): Scan for minimum in [25, 12, 22, 64] → min = 12 at index 2. Swap A[1] and A[2].
→ [11, **12**, 25, 22, 64]

**Pass 3** (i=2): Scan for minimum in [25, 22, 64] → min = 22 at index 3. Swap A[2] and A[3].
→ [11, 12, **22**, 25, 64]

**Pass 4** (i=3): Scan for minimum in [25, 64] → min = 25, already in place.
→ [11, 12, 22, **25**, 64]

**Final result: [11, 12, 22, 25, 64]** — sorted in 4 passes.

Note: Selection Sort always performs exactly **n(n−1)/2 comparisons** regardless of input order.

### Complexity Analysis

| Case | Time Complexity |
|---|---|
| Best | O(n²) |
| Average | O(n²) |
| Worst | O(n²) |

Space complexity: **O(1)**. The complexity is always O(n²) — unlike Bubble Sort, it has no best-case improvement.

**Advantages:** Fewer swaps than Bubble Sort, simple, in-place.
**Disadvantages:** Always O(n²) — no improvement for sorted input. Not stable.

## 3. Insertion Sort

### The Idea

Insertion Sort builds the sorted array **one element at a time**. Think of how you sort a hand of playing cards: you pick up one card at a time and insert it into the correct position among the cards you already hold.

The left portion is always sorted. For each new element, we find where it belongs in the sorted portion and shift everything else right to make room.

### Pseudocode

```
Algorithm InsertionSort(A, n):
  for i = 1 to n-1 do
    key = A[i]        // element to insert
    j = i - 1
    while j >= 0 and A[j] > key do
      A[j+1] = A[j]  // shift element right
      j = j - 1
    end while
    A[j+1] = key     // insert in correct position
  end for
```

### Worked Example

Sort: **A = [8, 3, 5, 2]**

**Step 1** (i=1, key=3): Compare 3 < 8, shift 8 right. Insert 3.
→ [**3**, **8**, 5, 2]

**Step 2** (i=2, key=5): Compare 5 < 8, shift 8 right. Compare 5 > 3, stop. Insert 5.
→ [3, **5**, **8**, 2]

**Step 3** (i=3, key=2): Compare 2 < 8, shift. Compare 2 < 5, shift. Compare 2 < 3, shift. Insert 2.
→ [**2**, 3, 5, 8]

**Final result: [2, 3, 5, 8]** — sorted in 3 steps.

### C Implementation

```c
// Insertion Sort — C implementation
void insertionSort(int A[], int n) {
    int i, j, key;
    for (j = 1; j < n; j++) {
        key = A[j];    // element to be positioned
        i = j - 1;
        // shift elements greater than key one position right
        while (i > -1 && A[i] > key) {
            A[i + 1] = A[i];
            i = i - 1;
        }
        A[i + 1] = key; // place key in correct position
    }
}
```

### Loop Invariant Proof

Insertion Sort's correctness can be proven formally using a **loop invariant**.

**Loop Invariant:** At the start of each iteration of the outer `for` loop, the subarray **A[0..i-1]** contains the elements originally in those positions, in **sorted order**.

- **Initialization:** Before the first iteration (i=1), A[0..0] contains one element — trivially sorted. ✓
- **Maintenance:** The body moves A[i] into its correct position within A[0..i], so A[0..i] is sorted after iteration i. ✓
- **Termination:** When i = n, A[0..n-1] — the whole array — is sorted. ✓

### Complexity Analysis

| Case | Condition | Time Complexity |
|---|---|---|
| Best | Array already sorted (no shifts needed) | O(n) |
| Average | Random order | O(n²) |
| Worst | Array in reverse order (maximum shifts) | O(n²) |

Space complexity: **O(1)**. Stable. Well-suited for small or nearly-sorted datasets.

**Advantages:** Fast for small datasets, adaptive (efficient for nearly-sorted data), stable, requires no extra memory.
**Disadvantages:** O(n²) worst case makes it unsuitable for large datasets.

## 4. Merge Sort

### The Idea

Merge Sort uses the **divide-and-conquer paradigm**:

1. **Divide:** Split the array in half
2. **Conquer:** Recursively sort each half
3. **Combine:** Merge the two sorted halves into one sorted array

The recursion reaches its base case when a subarray has only one element (already sorted). The real work happens in the merge step.

<DiagramBlock chart={`graph TD
    A["38 27 43 3 9 82 10"] --> B["38 27 43 3"]
    A --> C["9 82 10"]
    B --> D["38 27"]
    B --> E["43 3"]

    C --> G["10"]
    D --> H["38"]
    D --> I["27"]

    I --> L

    N --> R["3 9 10 27 38 43 82"]

### Pseudocode

```
Algorithm MergeSort(A, p, r):
  if p < r then
    q = (p + r) / 2
    MergeSort(A, p, q)       // sort left half
    MergeSort(A, q+1, r)     // sort right half
    Merge(A, p, q, r)        // merge sorted halves
  end if

Algorithm Merge(A, p, q, r):
  // Create temporary left and right arrays
  L = A[p..q]
  R = A[q+1..r]
  i = 0, j = 0, k = p
  while i < len(L) and j < len(R):
    if L[i] <= R[j]:
      A[k] = L[i]; i++
    else:
      A[k] = R[j]; j++
    k++
  // Copy any remaining elements
  copy remaining L or R elements into A
```

### Worked Example — The Merge Step

**Left:** [3, 27, 38] **Right:** [9, 10, 43]

| Step | Compare | Take | Result so far |
|---|---|---|---|
| 1 | 3 vs 9 | 3 (left) | [3] |
| 2 | 27 vs 9 | 9 (right) | [3, 9] |
| 3 | 27 vs 10 | 10 (right) | [3, 9, 10] |
| 4 | 27 vs 43 | 27 (left) | [3, 9, 10, 27] |
| 5 | 38 vs 43 | 38 (left) | [3, 9, 10, 27, 38] |
| 6 | — vs 43 | 43 (right, remaining) | [3, 9, 10, 27, 38, 43] |

**Merged result: [3, 9, 10, 27, 38, 43]** ✓

### Recurrence Relation

<FormulaBlock
  formula="T(n) = 2T\!\left(\frac{n}{2}\right) + n"
  label="Merge Sort recurrence"
/>

- **2T(n/2):** two recursive calls on halves of size n/2
- **n:** the merge step processes all n elements

Solving with the Master Theorem gives **T(n) = O(n log n)**.

**Why O(n log n)?**
- Number of levels in the recursion tree = log₂ n (each level halves the problem)
- At each level, total work across all merges = n
- Total work = n × log n = **O(n log n)**

### Complexity Analysis

| Case | Time Complexity |
|---|---|
| Best | O(n log n) |
| Average | O(n log n) |
| Worst | O(n log n) |

Space complexity: **O(n)** — requires extra memory for the temporary arrays during merge.

Merge Sort is the only common algorithm with **consistently O(n log n)** performance — unlike Quick Sort which degrades to O(n²) in the worst case.

**Advantages:** Stable, predictable O(n log n) always, excellent for linked lists and large datasets.
**Disadvantages:** Requires O(n) extra memory, slower than Quick Sort in practice for arrays.

## 5. Quick Sort

### The Idea

Quick Sort is also divide-and-conquer, but it partitions the array **around a pivot element**:

1. **Divide:** Choose a pivot. Rearrange so all elements < pivot are left of it, all elements > pivot are right of it
2. **Conquer:** Recursively sort the left and right subarrays
3. **Combine:** Nothing — the array is sorted in-place

### Pseudocode

```
Algorithm QuickSort(A, p, r):
  if p < r then
    q = Partition(A, p, r)   // pivot is now in correct position
    QuickSort(A, p, q-1)     // sort left of pivot
    QuickSort(A, q+1, r)     // sort right of pivot
  end if

Algorithm Partition(A, p, r):
  x = A[r]                   // pivot is last element
  i = p - 1
  for j = p to r-1 do
    if A[j] <= x then
      i = i + 1
      swap A[i] and A[j]
    end if
  end for
  swap A[i+1] and A[r]       // place pivot in correct position
  return i + 1
```

### The Partition Step Explained

**Partition maintains four regions:**
1. A[p..i] — elements ≤ pivot
2. A[i+1..j-1] — elements > pivot
3. A[j..r-1] — not yet examined
4. A[r] — the pivot itself

After Partition completes, the pivot is in its **final sorted position**.

### Worked Example

Sort: **A = [3, 6, 8, 10, 1, 2, 1]**, pivot = A[6] = 1

After partitioning around 1: [**1**, 1, 8, 10, 6, 2, 3] — wait, let us use a cleaner example.

Sort: **A = [8, 3, 7, 1, 5]**, pivot = A[4] = 5

- i = -1, j scans from 0 to 3:
  - j=0: A[0]=8 > 5, no swap
  - j=1: A[1]=3 ≤ 5, i becomes 0, swap A[0] and A[1] → [**3**, 8, 7, 1, 5]
  - j=2: A[2]=7 > 5, no swap
  - j=3: A[3]=1 ≤ 5, i becomes 1, swap A[1] and A[3] → [3, **1**, 7, 8, 5]
- Final: swap A[i+1]=A[2] with pivot A[4] → [3, 1, **5**, 8, 7]

Pivot 5 is now at index 2. Left subarray [3, 1] and right subarray [8, 7] are sorted recursively.

### Pivot Choice Matters

Choosing a **poor pivot** (always smallest or largest) causes O(n²) worst case:

```c
// Poor choice: always first element (bad if already sorted)
int key = A[p];

// Better choice: middle element
int keyPos = (p + j) / 2;

// Best for average case: random element
int keyPos = randomInRange(p, j);
```

### Complexity Analysis

| Case | Condition | Time Complexity |
|---|---|---|
| Best | Pivot always splits evenly | O(n log n) |
| Average | Random pivot | O(n log n) |
| Worst | Pivot always smallest/largest | O(n²) |

Space complexity: **O(log n)** average (recursion stack depth), **O(n)** worst case.

**Advantages:** Very fast in practice, in-place (O(1) extra memory for array), cache-friendly.
**Disadvantages:** O(n²) worst case, not stable. Worst case occurs on already-sorted arrays with naive pivot.

## Comparison Table

| Algorithm | Best | Average | Worst | Space | Stable |
|---|---|---|---|---|---|
| Bubble Sort | O(n) | O(n²) | O(n²) | O(1) | Yes |
| Selection Sort | O(n²) | O(n²) | O(n²) | O(1) | No |
| Insertion Sort | O(n) | O(n²) | O(n²) | O(1) | Yes |
| Merge Sort | O(n log n) | O(n log n) | O(n log n) | O(n) | Yes |
| Quick Sort | O(n log n) | O(n log n) | O(n²) | O(log n) | No |

**Lower bound for comparison sorting:** It can be mathematically proven using the **decision tree model** that any comparison-based sorting algorithm must perform at least **Ω(n log n)** comparisons in the worst case. Merge Sort and Heap Sort achieve this bound — they are asymptotically optimal.

<Analogy>
Imagine sorting a deck of playing cards. Bubble Sort is the impatient person who keeps swapping adjacent cards — slow and repetitive. Selection Sort is the methodical person who scans the whole deck for the smallest card each time. Insertion Sort is how most people actually sort cards — pick one up, slide it into the right spot. Merge Sort is a librarian who splits the deck in half repeatedly, sorts each pile separately, then merges them. Quick Sort is the gambler who picks a random card as a pivot and splits the deck around it — usually fast, occasionally unlucky.
</Analogy>

<Takeaway>
Bubble, Selection, and Insertion Sort are simple O(n²) algorithms good for small or nearly-sorted data. Merge Sort and Quick Sort are the serious O(n log n) algorithms. Merge Sort is always O(n log n) but needs extra memory. Quick Sort is fast in practice and in-place, but has an O(n²) worst case that can be avoided with random pivot selection. No comparison-based algorithm can beat O(n log n) — it is a mathematical lower bound.
</Takeaway>
