Some problems are naturally recursive: to solve the whole thing, you solve smaller versions of the same problem and combine the results. Divide and conquer formalises this idea into a three-step pattern that powers some of the most important algorithms in computer science — from Merge Sort to fast matrix multiplication.

---

## The Divide-and-Conquer Paradigm

Every divide-and-conquer algorithm follows three steps at each level of recursion:

1. **Divide** — Break the problem into smaller subproblems of the same type
2. **Conquer** — Solve the subproblems recursively. If a subproblem is small enough (the base case), solve it directly
3. **Combine** — Merge the subproblem solutions into a solution for the original problem

An algorithm is traditionally called divide-and-conquer only if it makes **two or more recursive calls**. (Binary Search makes only one recursive call — it is divide-and-conquer in spirit, but technically a decrease-and-conquer algorithm.)

<DiagramBlock chart={`graph TD
    A["Original Problem size n"] --> B["Subproblem 1<br/>size n/b"]
    A --> C["Subproblem 2<br/>size n/b"]
    A --> D["..."]
    B --> E["Sub-sub<br/>problems"]
    C --> F["Sub-sub<br/>problems"]
    E --> G["Base cases<br/>(solve directly)"]
    F --> G
    G --> H["Combine results upward"]
    H --> I["Final Solution"]
`} />

**Classic examples:**
- **Merge Sort** — divide array in half, sort each half, merge
- **Quick Sort** — partition around pivot, sort each partition
- **Binary Search** — divide search space in half, search one half
- **Matrix Multiplication (Strassen)** — divide matrices into blocks, multiply blocks

## Recursion — The Foundation

Before understanding divide-and-conquer fully, you need to understand recursion. A **recursive function** calls itself with a smaller version of the same problem.

**Two essential parts:**
1. **Base case** — the simplest version of the problem, solved directly (no recursion)
2. **Recursive step** — the function calls itself with a smaller input

Without a base case, recursion runs forever (stack overflow).

### Example 1: Factorial

Factorial of n is defined as: n! = n × (n−1) × (n−2) × … × 1

Recursive definition: n! = n × (n−1)!

```c
// Factorial — recursive implementation
long factorial(int n) {
    if (n <= 1)            // base case: 1! = 1
        return 1;
    else
        return n * factorial(n - 1);  // recursive step
}
```

**Trace for factorial(5):**

```
factorial(5) = 5 × factorial(4)
factorial(4) = 4 × factorial(3)
factorial(3) = 3 × factorial(2)
factorial(2) = 2 × factorial(1)
factorial(1) = 1   ← base case

Unwinding:
factorial(2) = 2 × 1 = 2
factorial(3) = 3 × 2 = 6
factorial(4) = 4 × 6 = 24
factorial(5) = 5 × 24 = 120
```

**Recurrence:** T(n) = T(n−1) + c (one recursive call + one multiplication)

Expanding: T(n) = T(n−1) + c = T(n−2) + 2c = … = T(1) + (n−1)c → **O(n)**

### Example 2: Fibonacci

```c
// Fibonacci — naive recursive implementation (inefficient)
long fibonacci(int n) {
    if (n == 0 || n == 1)     // base cases
        return n;
    return fibonacci(n-1) + fibonacci(n-2);  // two recursive calls
}
```

This is **O(2ⁿ)** — exponential — because each call branches into two more calls. The same subproblems are solved repeatedly. Dynamic programming fixes this (see that topic).

### Example 3: Towers of Hanoi

The classic puzzle: three rods, n discs of different sizes. Rules: move one disc at a time, never place a larger disc on a smaller one.

**Recursive thinking:**
1. Move top n−1 discs from source to helper rod
2. Move the largest disc from source to destination
3. Move n−1 discs from helper to destination

```
Hanoi(n, source, helper, destination):
  if n == 1:
    move disc from source to destination
    return
  Hanoi(n-1, source, destination, helper)  // move n-1 discs out of the way
  move disc from source to destination      // move largest disc
  Hanoi(n-1, helper, source, destination)  // stack n-1 discs on top
```

**Recurrence:**

<FormulaBlock
  formula="T(n) = 2T(n-1) + 1"
  label="Towers of Hanoi recurrence"
/>

Solving: T(1)=1, T(2)=3, T(3)=7, T(4)=15 → T(n) = 2ⁿ − 1 → **O(2ⁿ)**

This is exponential — moves grow very fast. For 64 discs, you need 2⁶⁴ − 1 ≈ 18 quintillion moves.

## Merge Sort — The Classic Divide-and-Conquer Sort

Merge Sort is the prototypical divide-and-conquer algorithm for sorting.

### The Three Steps

1. **Divide:** Split the n-element array into two subarrays of n/2 elements
2. **Conquer:** Recursively sort each half using Merge Sort
3. **Combine:** Merge the two sorted subarrays into one sorted array

The base case: an array of length 1 is already sorted — do nothing.

### Pseudocode

```
MergeSort(A, p, r):
  if p < r then                          // more than one element
    q = floor((p + r) / 2)              // find midpoint
    MergeSort(A, p, q)                  // sort left half
    MergeSort(A, q+1, r)                // sort right half
    Merge(A, p, q, r)                   // merge sorted halves
  end if
```

### The Merge Procedure

Merge takes two sorted subarrays and produces one sorted array by comparing elements one by one:

```
Merge(A, p, q, r):
  create arrays L = A[p..q]  and  R = A[q+1..r]
  i = 0, j = 0, k = p
  while i < len(L) and j < len(R):
    if L[i] <= R[j]:
      A[k] = L[i]
      i = i + 1
    else:
      A[k] = R[j]
      j = j + 1
    k = k + 1
  copy remaining elements of L (if any) into A[k..]
  copy remaining elements of R (if any) into A[k..]
```

### Full Worked Example

Sort: **A = [38, 27, 43, 3]**

**Divide phase:**
- Split [38, 27, 43, 3] → [38, 27] and [43, 3]
- Split [38, 27] → [38] and [27]
- Split [43, 3] → [43] and [3]

**Conquer (base cases reached):** [38], [27], [43], [3] — each single element is sorted

**Combine (merge phase):**
- Merge [38] and [27]: compare 38 > 27 → take 27, then 38 → [27, 38]
- Merge [43] and [3]: compare 43 > 3 → take 3, then 43 → [3, 43]
- Merge [27, 38] and [3, 43]:
  - Compare 27 vs 3: take 3 → [3]
  - Compare 27 vs 43: take 27 → [3, 27]
  - Compare 38 vs 43: take 38 → [3, 27, 38]
  - Take remaining 43 → [3, 27, 38, 43]

**Final result: [3, 27, 38, 43]** ✓

### Recurrence Relation

<FormulaBlock
  formula="T(n) = 2T\!\left(\frac{n}{2}\right) + n"
  label="Merge Sort recurrence"
/>

- **2T(n/2):** two recursive calls on halves
- **n:** the merge step scans all n elements

**Recursion tree analysis:**
- Level 0: one problem of size n → n work
- Level 1: two problems of size n/2 → 2 × n/2 = n work
- Level 2: four problems of size n/4 → 4 × n/4 = n work
- ...
- Level log n: n problems of size 1 → n × 1 = n work

Total work = n per level × log n levels = **O(n log n)**

## Matrix Multiplication

### The Standard Method

To multiply two n×n matrices A and B to get C = A×B:

Each entry C[i][j] = sum of A[i][k] × B[k][j] for k = 1 to n

```c
// Standard matrix multiplication — O(n³)
for (i = 0; i < n; i++) {
    for (j = 0; j < n; j++) {
        C[i][j] = 0;
        for (k = 0; k < n; k++) {
            C[i][j] += A[i][k] * B[k][j]; // n multiplications per entry
        }
    }
}
```

For each of n² entries, we perform n multiplications → **T(n) = O(n³)**

### Divide-and-Conquer Approach

Partition each n×n matrix into four (n/2)×(n/2) submatrices:

<FormulaBlock
  formula="C = \begin{pmatrix} C_{11} & C_{12} \\ C_{21} & C_{22} \end{pmatrix} = \begin{pmatrix} A_{11}B_{11} + A_{12}B_{21} & A_{11}B_{12} + A_{12}B_{22} \\ A_{21}B_{11} + A_{22}B_{21} & A_{21}B_{12} + A_{22}B_{22} \end{pmatrix}"
  label="Block matrix multiplication"
/>

This gives 8 recursive multiplications of (n/2)×(n/2) matrices, plus additions:

<FormulaBlock
  formula="T(n) = 8T\!\left(\frac{n}{2}\right) + O(n^2)"
  label="Standard divide-and-conquer matrix recurrence"
/>

Using the Master Theorem: this gives **T(n) = O(n³)** — no improvement over the standard method.

### Strassen's Algorithm

Strassen (1969) discovered that 8 recursive multiplications can be reduced to **7** using clever algebraic combinations:

Define 7 products P₁ through P₇ (each combining sums/differences of submatrices), then express C₁₁, C₁₂, C₂₁, C₂₂ in terms of those 7 products.

**Recurrence with Strassen:**

<FormulaBlock
  formula="T(n) = 7T\!\left(\frac{n}{2}\right) + O(n^2)"
  label="Strassen's recurrence"
/>

Using the Master Theorem (case 1): **T(n) = O(n^log₂(7)) ≈ O(n^2.81)**

| Method | Recurrence | Complexity |
|---|---|---|
| Standard | 8T(n/2) + O(n²) | O(n³) |
| Divide & Conquer | 8T(n/2) + O(n²) | O(n³) |
| Strassen | 7T(n/2) + O(n²) | O(n^2.81) |

Strassen's improvement matters enormously at large scales. Going from 8 to just 7 multiplications in the recursion changes the exponent from 3 to 2.81.

## Recurrence Relations

A recurrence relation expresses T(n) — the running time of a recursive algorithm — in terms of smaller input sizes.

**General form:**

<FormulaBlock
  formula="T(n) = aT\!\left(\frac{n}{b}\right) + f(n)"
  label="Divide-and-conquer recurrence general form"
/>

Where:
- **a** = number of subproblems
- **n/b** = size of each subproblem
- **f(n)** = work done outside the recursive calls (divide + combine steps)

**Algorithm-to-recurrence mapping:**

| Algorithm | a | b | f(n) | Recurrence |
|---|---|---|---|---|
| Factorial | 1 | — | c | T(n) = T(n−1) + c |
| Binary Search | 1 | 2 | c | T(n) = T(n/2) + c |
| Merge Sort | 2 | 2 | n | T(n) = 2T(n/2) + n |
| Strassen | 7 | 2 | n² | T(n) = 7T(n/2) + n² |

---

## The Master Theorem — Solving Recurrences Fast

The Master Theorem solves recurrences of the form T(n) = aT(n/b) + f(n) in one step.

Compare f(n) with n^(log_b a):

**Case 1:** If f(n) = O(n^(log_b a − ε)) for some ε > 0 (f grows slower than n^(log_b a)):

<FormulaBlock
  formula="T(n) = \Theta(n^{\log_b a})"
  label="Master Theorem Case 1"
/>

**Case 2:** If f(n) = Θ(n^(log_b a)) (f grows at the same rate):

<FormulaBlock
  formula="T(n) = \Theta(n^{\log_b a} \log n)"
  label="Master Theorem Case 2"
/>

**Case 3:** If f(n) = Ω(n^(log_b a + ε)) for some ε > 0 (f grows faster than n^(log_b a)):

<FormulaBlock
  formula="T(n) = \Theta(f(n))"
  label="Master Theorem Case 3"
/>

### Worked Examples

**Example 1: Merge Sort** — T(n) = 2T(n/2) + n
- a=2, b=2, f(n)=n
- n^(log_b a) = n^(log₂ 2) = n^1 = n
- f(n) = n = Θ(n) → Case 2
- **T(n) = Θ(n log n)** ✓

**Example 2: Binary Search** — T(n) = T(n/2) + c
- a=1, b=2, f(n)=c (constant)
- n^(log₂ 1) = n^0 = 1
- f(n) = c = Θ(1) → Case 2
- **T(n) = Θ(log n)** ✓

**Example 3: Strassen** — T(n) = 7T(n/2) + n²
- a=7, b=2, f(n)=n²
- n^(log₂ 7) ≈ n^2.81
- f(n) = n² = O(n^(2.81 − ε)) → Case 1
- **T(n) = Θ(n^log₂(7)) ≈ Θ(n^2.81)** ✓

**Example 4: Standard Divide-and-Conquer Matrix** — T(n) = 8T(n/2) + n²
- a=8, b=2, f(n)=n²
- n^(log₂ 8) = n^3
- f(n) = n² = O(n^(3−1)) → Case 1
- **T(n) = Θ(n³)** ✓

## Recursion vs Iteration — When to Use Which

| Feature | Recursion | Iteration |
|---|---|---|
| Control structure | Selection (if/else) | Repetition (for/while) |
| Termination | Base case reached | Loop condition fails |
| Memory | Extra stack frames each call | No extra stack usage |
| Clarity | Natural for tree/divide problems | Better for simple loops |
| Risk | Stack overflow if base case missing | Infinite loop if condition wrong |

**Demerits of recursion:** Each recursive call creates a new stack frame (copy of local variables), consuming memory. For deep recursion, this overhead can be significant. Iteration does not have this cost.

<Analogy>
Divide and conquer is like organising a large office filing system. You have 1,000 folders to sort. Instead of sorting all 1,000 yourself, you split the pile in half and give each half to an assistant. Each assistant splits their pile again and delegates. This continues until everyone has 1 folder (trivially sorted). Then everyone passes their sorted pile up the chain, and each level merges two sorted piles. The total work is distributed across log n levels, with n total work per level — hence O(n log n).
</Analogy>

<Takeaway>
Divide-and-conquer breaks a problem into smaller subproblems, solves them recursively, and combines the results. The running time of any divide-and-conquer algorithm is captured by a recurrence relation T(n) = aT(n/b) + f(n). The Master Theorem solves this recurrence in one step by comparing f(n) to n^(log_b a). Merge Sort is the canonical example: T(n) = 2T(n/2) + n → O(n log n). Strassen reduced 8 matrix multiplications to 7, changing the complexity from O(n³) to O(n^2.81).
</Takeaway>

Common mistake: applying the Master Theorem to T(n) = T(n−1) + c — the theorem only applies to T(n) = aT(n/b) + f(n) form, not T(n−1) form.
</ExamTip>
